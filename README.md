# AccessHub · 统一权限管理前端

根据《统一权限管理系统需求》实现的 Vue 3 管理后台，使用 Vite 与 Lucide 图标，适配桌面和移动端。

## 启动

```sh
npm install
npm run dev
```

默认访问 http://localhost:5173。生产构建：`npm run build`，构建输出在 `dist/`。

## 测试

需要安装 Node.js 及 Google Chrome。项目使用 Chrome 运行 Playwright 测试，不需要使用 Codex 自带运行时。

在 PowerShell 中进入项目并执行：

```powershell
cd E:\projects\system-front
npm.cmd install
npm.cmd test
```

测试命令会自动启动端口 5174 的测试服务并在结束后关闭；请保持 5174 空闲，无需先执行 `npm run dev`。每次测试使用独立浏览器上下文，不会修改你日常浏览器的演示数据。

测试覆盖临时账号必填用途、手机号精确唯一性、暂停恢复、批量授权与回收、部门冻结、HR 自动调岗处理、角色与菜单创建、账号退出与刷新状态，以及移动布局。全部用例显示 passed 表示通过。失败时可在 `test-results/` 查看截图与跟踪文件。

```powershell
npm.cmd run test:ui   # 打开测试界面，查看每一步
npm.cmd run build     # 验证生产构建
npm.cmd run preview   # 预览构建产物，访问终端显示的地址
```

如果没有 Chrome，可以改用 Playwright 自带 Chromium：

```powershell
npx.cmd playwright install chromium
$env:PLAYWRIGHT_CHANNEL = 'chromium'
npm.cmd test
```

手动测试：先执行 `npm.cmd run dev`，打开终端显示的地址；填写姓名、手机号、部门和用途创建一个无工号的临时账号，为其授予和回收“普通员工”角色，观察角色列表变化。也可以试验账号暂停恢复、部门冻结与日志导出；点击管理员头像选择“退出账号”，刷新后应仍显示已退出状态。

## 页面与交互

- 工作台：三项核心数量与待处理事项。
- 用户账号：查询和筛选、必填用途的临时账号创建、来源展示、手动账号暂停与恢复、详情。正式/外包员工为 HR 来源，离职账号保留。
- 角色管理：新建和编辑角色，配置允许访问的菜单，遵循 RBAC0 权限并集。
- 应用管理：OA、考勤、权限平台三套演示应用，支持菜单与多 API 映射配置。
- 权限分配：保持紧凑批量操作栏，选择用户、授予/回收操作和角色，直接填写必填授权理由或回收理由。回收时单条有效依据自动定位，多条依据在弹窗明确选择；其他依据保留，最后一条有效依据撤销后角色失效，理由写入审计。仅从具体调岗记录进入时关联该记录；直接授权在弹窗填写真实业务依据编号，同一依据分别登记到批量用户，不根据员工状态猜测来源。
- 人员与组织变动：HR 事件自动按旧部门和旧岗位授权依据回收，再自动更新所属部门；其他合法依据保留，页面按钮只读处理结果、部门冻结和解冻。
- 操作日志：演示操作记录、查询、CSV 导出。

## 数据及接入边界

当前为独立前端原型，所有业务数据存储于浏览器 localStorage。工作台只保留核心数量与待办；人员变动和部门冻结通过标签切换。API 详情按需展开。可在浏览器开发者工具中清除 `access-*` 项恢复初始演示数据。授权界面按详细设计/API v3 调整：新部门在 HR 完成旧权限处理后即可授权，回收结果仅供查看，不设置人工确认或完成交接步骤。手工授权必须填写已核实的真实业务依据编号，OA 审批授权由可信服务回调执行，前端不模拟批准 OA 事件。管理员资格、全局资源 ID、后端版本校验、幂等批次和部分失败响应仍需真实服务接入。

生产系统必须对接后端：账号/手机号密码登录、JWT 签发、每次 API 鉴权、HR/OA 回调、真实加密和非对称签名、永久审计、备份、管理员数据范围与分级授权校验。前端演示不能提供这些安全保证。OA 审批不在本系统内实现；不包含角色先决约束及自动过期。

界面手机号统一脱敏；本地原型不存储真实密码。权限平台自身菜单和 API 已纳入演示资源，临时账号无工号，用户名由服务端生成，使用结束后手动暂停；本人短信验证设密前不能登录。HR 同步账号的状态由 HR 事件更新。


管理员头像弹窗提供退出账号。当前退出清除前端登录状态并保存在 sessionStorage，刷新不会自动进入后台；业务数据仍保留。由于项目尚无认证后端，“重新进入管理后台”仅用于本地原型，生产接入时应替换为真实登录流程，并在退出时撤销服务端会话及清除凭证。
